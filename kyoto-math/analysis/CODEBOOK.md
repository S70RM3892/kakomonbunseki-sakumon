# 京大理系数学 過去問分析コードブック

各年度の問題を同じ物差しで記録するための基準。元データは `build.py` の表 `P` に1パート1行で持ち、`python3 build.py` で `data/YYYY.json` と `years/YYYY.md` を生成する。手で直すのは `build.py` だけ。

## 分析単位

大問(1〜6)。大問が互いに独立な「問1・問2」に分かれる小問集合(2019・2021・2023・2025)は、各問を1パートとする。配点は大問単位でしか公表されていないので、問1に大問の配点を入れ、問2は 0(=問1に合算)とする。

## 分野(field)

主分野を次から1つ。残りは `sub_fields` に書く。

`積分` `微分` `極限` `確率・場合の数` `整数` `空間図形` `平面図形` `複素数平面` `軌跡・領域` `数列` `多項式` `数と式`

- 融合問題は「答案の大半を何に使うか」で主分野を決める。例: 確率漸化式は `確率・場合の数`(副: 数列)、回転体の体積は `積分`(副: 空間図形)。
- 2次曲線が主題の問題は `軌跡・領域` に入れ、副分野に `2次曲線` と書く。
- ベクトルで解く空間の問題は `空間図形`(副: ベクトル)。

## 形式(format)

`求値` / `証明` / `図示` とその組合せ。京大は求値問題でも過程を採点する(公式の出題意図に明記)ので、形式は「最終的に何を答えるか」だけを表す。

## 誘導(guide)

| 記号 | 定義 |
|---|---|
| G0 | 小問なし。問題文1つに答1つ |
| G1 | 小問はあるが互いに独立、または前の小問が後の小問をほとんど助けない |
| G2 | 前の小問が後の小問の本質的な手がかりになっている |

`num_subq` は (1)(2)… の個数(G0 なら 0)。

## 難易度(difficulty)

京大工学部の合格ライン付近の受験生が、150 分のうち 20〜30 分を使ったときの見込みで4段階。

| 段階 | 意味 | 本番での扱い |
|---|---|---|
| 易 | 方針が一本道で、計算も短い | 完答必須。落とすと取り返せない |
| 標準 | 定番の手法で解けるが、どこかに落とし穴か計算の山がある | 合否を分ける。ここを何題完答するかの勝負 |
| やや難 | 方針の発見か、論証・計算の完遂のどちらかが重い | 部分点を拾う。完答は余力次第 |
| 難 | 方針も完遂も重い | 着手は最後。書けることだけ書く |

この判定は分析者(AI)が自分で解いたうえでの見立てで、予備校の講評との照合はしていない(`trend.md` の「限界」参照)。

## 型(patterns)

解法の核になる動作を短い句で2〜4個。作問のときに「どの動作を要求する問題にするか」を選ぶための索引。

## 答(answer)と確認(checked)

- `計算機`: 数式処理または数値計算で検算した(総当たり、数値積分との一致など)
- `手計算`: 分析者が手で導いた。計算機での検算はしていない
- `証明問題`: 答の値がない

公式の解答例との照合はしていない。作問や自己採点に使う前に赤本などで確認すること。

## 年度別 Markdown の構成

`years/YYYY.md` は「全体」のあと大問ごとに、分野・形式・要旨・解法の核心・型・答・作問メモを並べる。問題文の逐語的な転記はしない(要旨と構造だけ)。
